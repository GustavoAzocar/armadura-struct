# AS-53 · Duplicar a armadura completa

Selecione uma armadura e use **Elementos → Duplicar completa** (comando `DUPLICAR` ou `CLONAR`). A prévia mostra as novas peças físicas, objetos gráficos, marcas e a massa líquida antes/depois. Escolha deslocamento em mm, destino e posição de fabricação. **Cancelar** conserva o projeto. A aplicação inteira ocupa uma entrada de desfazer/refazer.

**Copiar** (`C`, ponto base, ponto destino) também copia o grafo completo das armaduras selecionadas. Objetos gráficos avulsos explicitamente selecionados acompanham uma única vez; copiar somente gráficos preserva a armadura física e seu quantitativo. Uma cópia avulsa da inserção principal passa a mostrar somente a marca.

## Objetos e vínculos

Cada armadura física copiada recebe outro ID, origem local de rastreabilidade e marca livre conforme a política AS-55. A cópia inclui geometria, metadados, terminações/variante existentes, distribuição própria, todas as inserções, anotações vinculadas e linhas auxiliares associadas. Os IDs internos são remapeados; a definição original não muda. Inserções e chamadas continuam atualizando a partir da nova armadura.

A translação é aplicada uma vez: origem física, extremidades da distribuição no modelo, origens das inserções e pontos dos auxiliares. Pontos locais da barra, dimensões físicas, escala/rotação da inserção e origem local de sua chamada permanecem iguais. Máscaras explicitamente selecionadas são copiadas com sua origem deslocada e primitivas locais intactas. Nenhuma geometria é associada por proximidade.

Em **Propriedades → Vínculos de cópia**, selecione as armaduras associadas a uma polilinha ou anotação. `Annotation.barId` continua sendo o vínculo principal da descrição automática. `barIds` guarda vínculos auxiliares adicionais; uma polilinha usa apenas `barIds`. Estes vínculos não criam aço nem modificam quantidades.

Quando um auxiliar se refere a outras armaduras, a cópia exige uma escolha:

- **Manter vínculos**: copia o auxiliar, remapeia os vínculos das armaduras copiadas e conserva referências às outras originais. Não altera o auxiliar de origem.
- **Duplicar conjunto conectado**: a prévia inclui todas as armaduras conectadas, transitivamente, e remapeia os vínculos para suas cópias. Nenhuma outra armadura é criada antes dessa escolha.

**Nova posição livre** cria outra posição de fabricação. **Reutilizar posição equivalente** acrescenta a ocorrência à posição existente pela regra AS-54, conservando a rastreabilidade. A quantidade física aumenta nas duas opções. Editar uma cópia que deixe de ser equivalente separa sua posição automaticamente. A opção de equivalência global fica indisponível durante edição isolada, respeitando a proteção AS-02.

Sem destino explícito, cada objeto conserva seu desenho de origem. No comando `C`, o destino é o detalhamento ativo, como no fluxo anterior. Na edição isolada, os novos objetos ficam no detalhe em edição; operações que modificariam objetos externos são recusadas. Quantidades continuam sendo base × multiplicador × repetição do **detalhamento de destino**. A repetição não é incorporada novamente na barra.

## API pública

```ts
import { executeRebarBatch, applyRebarBatch } from './src/api';

const result = executeRebarBatch(
  project,
  [
    {
      type: 'armature.clone',
      barIds: ['original'],
      delta: { x: 3500, y: 0 },
      shared: 'keep', // obrigatório se existir dependência compartilhada
      position: 'new', // ou 'equivalent'
      ids: { original: 'variante' }, // opcional: ID novo por objeto de origem
    },
  ],
  { units: 'mm' },
);
project = applyRebarBatch(project, result);
```

`objectIds` inclui gráficos selecionados, inclusive máscaras e gráficos sem vínculo. `detailId` escolhe o destino. IDs omitidos no mapa são gerados; colisões globais, IDs inexistentes e chaves fora do grafo são recusados. A API conserva o estado original em qualquer falha do lote. `receipt.createdIds` lista o conjunto novo. A API `bar.copy` delega à mesma cópia profunda, com `newId` para a nova armadura, e aceita `shared`/`position`.

`armature.bind` recebe `objectIds` de anotações/polilinhas e `barIds`; `[]` limpa os vínculos auxiliares, preservando o vínculo principal da chamada. IDs físicos precisam existir. A exclusão física continua exigindo política explícita para referências; `references: 'remove'` remove inserções/chamadas principais próprias e auxiliares exclusivos, e retira o ID de auxiliares compartilhados sobreviventes.

`planArmatureClone(project, options)` consulta o grafo, objetos compartilhados e referências externas. `cloneArmatureGraph(project, options)` é a transformação imutável de baixo nível, retornando `project`, `idMap` e `createdIds`; use `executeRebarBatch`/`applyRebarBatch` como fronteira de validação completa e aplicação transacional. `REBAR_CAPABILITIES.deepArmatureCopy` e `sharedClonePolicies` anunciam o suporte; a API 1.0 recebe estas operações aditivas.

RA automática acompanha a cópia. RA bloqueada conserva a fotografia e indica mudança pendente, conforme AS-51; geradores podem solicitar `schedule: 'invalidate-lock'` fora da edição isolada. A prévia informa a massa líquida atual, sem usar a fotografia bloqueada.

## Persistência, exemplo e limites

O projeto usa **`armadurastruct/13`**, lendo formatos 1–12. O pacote usa **`openstruct.detail/7`**, lendo 1–6. Os campos auxiliares são opcionais: projetos antigos conservam IDs, coordenadas, quantitativos e vínculos existentes. Não se inferem vínculos de linhas antigas. Versões anteriores com novos campos são recusadas para impedir perda silenciosa. Pacotes incluem definições de dependências externas, sem importá-las como aço automaticamente; a atualização seletiva AS-08 permite reassociar/desvincular cada referência auxiliar. Consulte o [JSON Schema v7](openstruct-detail-v7.schema.json).

Execute `npm run example:clone -- /tmp/variante.armstruct.json` e abra o JSON no editor. O [exemplo TypeScript](examples/armature-clone.ts) cria 8 peças Ø10, duas inserções, chamada e auxiliar; duplica com IDs determinísticos e altera somente a variante para Ø12,5. Os testes conferem massa analítica, independência, remapeamento, colisões, lotes atômicos, edição isolada, versões e intercâmbio. O fluxo de navegador verifica cópia, prévia, cancelamento, equivalência, vínculos, salvar/reabrir e desfazer/refazer.

O modelo atual possui uma distribuição própria por barra. **Faixas físicas de várias posições e famílias variáveis ainda não implementadas não são introduzidas por esta tarefa**; a escolha compartilhada cobre os vínculos explícitos existentes de anotações e auxiliares. Escalas e representações não fabricam aço. Esta é uma operação de detalhamento, sem dimensionamento ou verificação normativa. Referência conceitual: [TQS · DeepCopy e linhas adicionais](https://docs.tqs.com.br/Docs/Details?id=1474000011&language=pt-BR); não há dependência do SDK proprietário nem adoção de critérios históricos como norma vigente.
