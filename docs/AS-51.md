# AS-51 · API executável de armaduras

Atualização AS-03: o projeto nativo atual é `armadurastruct/7`, com quantidade base em `Bar.quantity` e efetiva em `schedule(...).quantity`. A fachada também exporta `setDetailRepetition`, `barQuantities`, `detailTitle` e a prévia/aplicação de reunião; consulte [AS-03](AS-03.md). As operações de posição/faixa abaixo conservam a quantidade base e reutilizam o fator do detalhe.

A fachada pública é [`src/api.ts`](../src/api.ts). É TypeScript de domínio, sem React, DOM, servidor HTTP ou dependência de um SDK proprietário. Cria/edita posições físicas e associa as representações já existentes no modelo. O pacote de intercâmbio continua sendo a **AS-09**; esta API executa operações em memória e não define outro formato de arquivo.

## Versão, unidades e capacidades

`REBAR_API_VERSION` é `"1.0"`. `REBAR_CAPABILITIES` informa versão, unidades, famílias, operações disponíveis, limite de lote e quantidade de distribuições por posição. As famílias discriminadas são `kind: "free"` (poligonal livre) e `kind: "stirrup"` (estribo retangular atual com dois ganchos de 135°). Não há criação de famílias ainda não implementadas.

Todas as medidas lineares são **mm**, inclusive bitola, mandril, gancho, coordenadas e espaçamento. Ângulos são graus; quantidades são inteiras. `units: "mm"` é obrigatório em cada chamada. A API recusa outra unidade, sem tentar inferi-la pelo valor numérico. Para receber dados em cm/m use a conversão do pacote AS-09 ou converta explicitamente no produtor.

O parâmetro `apiVersion` é opcional e assume a versão atual. Versões desconhecidas são recusadas. Mudanças incompatíveis exigem nova versão principal; novas capacidades devem ser declaradas e consultadas antes do uso. O contrato 1.0 publicado aqui é o escopo suportado, sem prometer métodos de outras bibliotecas. O projeto salvo permanece `armadurastruct/6`, sem migração adicional nesta tarefa.

## Executar e aplicar uma transação

```ts
import {
  executeRebarBatch,
  applyRebarBatch,
  type RebarCommand,
} from './src/api';
import { emptyProject } from './src/domain/model';

const current = emptyProject();
const detailId = current.hierarchy.details[0].id;
const commands: RebarCommand[] = [
  {
    type: 'bar.create',
    id: 'gerador-barra-01',
    detailId,
    definition: {
      kind: 'free',
      mark: 'N1',
      diameter: 10,
      mandrel: 50,
      steel: 'CA-50',
      quantity: 3,
      points: [
        { x: 0, y: 0 },
        { x: 1000, y: 0 },
      ],
    },
  },
  {
    type: 'representation.create',
    id: 'vista-barra-01',
    barId: 'gerador-barra-01',
    origin: { x: 0, y: -300 },
  },
];
const result = executeRebarBatch(current, commands, {
  apiVersion: '1.0',
  units: 'mm',
});
if (!result.ok) {
  console.error(result.issues); // current permanece intacto
} else {
  const next = applyRebarBatch(current, result);
  // Entregue next ao histórico UMA vez, ou serialize pelo formato nativo existente.
  console.log(result.receipt.createdIds);
}
```

`executeRebarBatch` é síncrona e não altera o projeto ou os comandos de entrada. Cada comando é validado antes de entrar no estado temporário. As operações são sequenciais: crie uma posição antes de referenciá-la. Os IDs explícitos permitem ligações entre operações do mesmo lote; quando omitidos nas criações, a API gera IDs e os retorna no recibo. IDs atualizados permanecem estáveis; renomear uma marca não muda os vínculos.

O lote aceita de 1 a 10000 operações. Se qualquer operação falhar, retorna `ok: false`, `project === current`, sem recibo de sucesso ou objetos parciais. Alterações anteriores daquele lote também são descartadas. Não há publicação do estado temporário. O chamador deve tratar projetos/resultados como valores imutáveis, sem editar seus objetos diretamente; objetos inalterados podem ser compartilhados entre estados para preservar o desempenho e o histórico.

`applyRebarBatch` recusa falhas e resultados calculados sobre outra instância do projeto, com erro `STALE_BATCH`. Não cria histórico sozinho: o host confirma seu resultado uma vez. Na interface, os comandos e lotes passam pela transação existente; desfazer/refazer trata uma operação sobre várias posições como uma única etapa.

## Operações suportadas

| Operação                | Dados principais e comportamento                                                                                                                                               |
| ----------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------- |
| `bar.create`            | `detailId`, `id?`, `definition`, `provenance?`. Cria uma posição física completa, com marca única. ID/origem em conflito exige atualização explícita.                          |
| `bar.update`            | `id`, `patch` discriminado por `kind`. Atualiza campos da família existente; não troca família implicitamente nem aceita `hook` em uma barra livre.                            |
| `bar.delete`            | `id`, `references?: "reject"                                                                                                                                                   | "remove"`. Por padrão recusa uma posição referenciada. `remove` exclui explicitamente suas chamadas/rebatimentos junto com a definição física. |
| `bar.move`              | `id`, `delta`. Move a origem física e a faixa associada, preservando comprimento e quantidade. Representações com origem própria permanecem independentes.                     |
| `bar.copy`              | `id` da origem, `newId?`, `detailId?`, `mark?`, `delta`. Cria outra posição física e outra quantidade de aço. Não copia a proveniência ou todos os gráficos da posição antiga. |
| `bar.transform`         | `id`, `operation: "rotate"                                                                                                                                                     | "mirror"`. Reutiliza as transformações atuais; espelhar um estribo produz a poligonal livre equivalente, explicitamente por este comando.      |
| `bar.split`             | `id`, `station`, `lap`, ambos em mm. Reutiliza a divisão em trecho reto, preservando o primeiro ID e retornando o segundo no recibo.                                           |
| `bar.join`              | `ids: [id1, id2]`. Une poligonais compatíveis coincidentes no mesmo detalhe e reassocia os vínculos, sem soldar lacunas silenciosamente.                                       |
| `bar.renumber`          | Renumera marcas pelo fluxo existente; preserva IDs e vínculos. Operação global, sujeita à proteção de edição isolada.                                                          |
| `distribution.set`      | `barId`, `distribution: {start?, end, render?}`, `count`. Associa/substitui a faixa existente e calcula a quantidade.                                                          |
| `distribution.remove`   | `barId`. Remove a representação da distribuição; conserva a quantidade física atual.                                                                                           |
| `representation.create` | `id?`, `barId`, `origin`, `detailId?`. Cria rebatimento sem adicionar aço; dono padrão é o detalhe da barra.                                                                   |
| `representation.update` | `id`, `origin?`, `barId?`. Mantém o ID gráfico e atualiza a origem ou reassocia a uma posição existente.                                                                       |
| `representation.delete` | `id`. Exclui somente o rebatimento, sem retirar aço físico.                                                                                                                    |

Uma definição exige bitola, mandril, aço e quantidade. Barra livre exige `points`; estribo exige `width`, `height`, `hook`. `origin`, `rotation`, `color`, `element` e `mark` são opcionais: o padrão de apresentação é o existente no editor, a origem é (0,0), a rotação é zero, a descrição usa o elemento estrutural e a marca é a próxima N livre. As propriedades físicas não são deduzidas de normas. A origem geométrica da barra e a origem de um rebatimento são dados distintos.

O `patch` exige o discriminante `kind`, mesmo quando altera apenas quantidade/bitola. Um comando deve levar todos os campos necessários para terminar válido; não é permitido primeiro gravar uma geometria inválida para depois completá-la. O validador reutiliza o modelo e o cálculo de dobras existentes, verifica IDs/marcas, números finitos, limites, distribuição e referências. Geometrias legadas já inválidas continuam abrindo; uma alteração nessa posição precisa corrigi-la integralmente. Alterar outro objeto não apaga o legado.

Para uma distribuição por espaçamento máximo:

```ts
const distribution: RebarCommand = {
  type: 'distribution.set',
  barId: 'gerador-barra-01',
  distribution: { end: { x: 1000, y: 0 }, render: 'ticks' },
  count: { mode: 'spacing', spacing: 150 },
};
// ceil(1000/150) + 1 = 8 peças, incluindo ambas as extremidades.
// Alternativa: count: { mode: 'quantity', quantity: 8 }
```

Há **uma faixa por posição** no contrato/modelo atual. A faixa define as ocorrências gráficas dessa quantidade, não outras definições físicas. Rebatimentos e vistas adicionais não multiplicam o quadro. Comprimento/peso e desenhos são derivados da mesma posição; mudar gancho/bitola atualiza a geometria e todas as representações vinculadas sem manter cópias de aço ou caches independentes.

## Erros, escopo e relação de aço

Cada erro tem `code`, `message`, `field`, `objectId?` e `operationIndex?` (índice começando em zero). Exemplos de códigos: `INVALID_FIELD`, `INVALID_GEOMETRY`, `INVALID_DISTRIBUTION`, `NOT_FOUND`, `FAMILY_MISMATCH`, `ID_CONFLICT`, `MARK_CONFLICT`, `REFERENCE_IN_USE`, `SOURCE_CONFLICT`, `SCOPE_VIOLATION`, `UNSUPPORTED_UNIT`, `UNSUPPORTED_VERSION` e `STALE_BATCH`. Erros de campo carregam caminhos como `patch.hook`, `definition.points.1.x` ou `count.spacing`. `RebarApiError` mantém os erros estruturados e uma mensagem legível quando o host usa `applyRebarBatch`.

`scopeDetailId` ativa o contrato de edição isolada da AS-02. Criar/alterar/remover objetos de outro detalhe ou remover suas referências faz o lote inteiro falhar. Ler uma posição externa para criar uma representação no detalhe atual é permitido, sem editar sua definição. O host é responsável por fornecer o escopo atual; isso é proteção de edição, não autenticação de usuários.

`schedule: "preserve-lock"` é o padrão: mantém a RA bloqueada e informa `scheduleDirty` se os dados mudaram, como na edição manual atual. `schedule: "invalidate-lock"` devolve a RA ao cálculo automático quando os dados do quadro mudam; uma alteração apenas gráfica não invalida o bloqueio. A invalidação global é recusada durante edição isolada com RA bloqueada. A AS-09 continua com sua política explícita de invalidação ao importar alterações físicas.

O recibo de sucesso contém versão, operações/IDs, `createdIds`, `updatedIds`, `deletedIds`, `affectedViews`, `steelChanged`, `scheduleDirty` e `scheduleInvalidated`. Os conjuntos de IDs representam a diferença final entre estados, incluindo gráficos removidos por exclusão explícita. `steelChanged` também considera identificação/descrição que alteram os dados da RA; não significa exclusivamente mudança de peso. Posição, escala e rotação das vistas não são alteradas pela API.

## Exemplos executáveis e integração

```bash
npm ci
npm run example:rebar -- rebar-example.armstruct.json
```

[`docs/examples/rebar-api.ts`](examples/rebar-api.ts) cria uma barra livre, um estribo e uma distribuição com as operações públicas. [`scripts/examples/rebar-api.mjs`](../scripts/examples/rebar-api.mjs) executa o TypeScript em Node com o Vite já usado pelo projeto, sem navegador, escreve o projeto nativo e informa os totais. O exemplo gera **2 posições e 11 peças**. Abra o arquivo pela interface e use as mesmas propriedades para editar gancho/bitola. Não é necessário gerar outro protocolo ou iniciar um servidor HTTP.

Para enviar um detalhe a outro projeto, passe o projeto resultante à função `createDetailPackage` da AS-09. O gerador pode fornecer `provenance: {projectId, objectId}` estável na criação para manter uma identidade externa; a mesma origem já existente é recusada como nova posição. As rotinas AS-08/09 continuam responsáveis pela comparação/revisão seletiva dos pacotes. Não há alteração dos repositórios de outros aplicativos nesta tarefa.

## Limites reais

A API reflete as famílias e a geometria atuais. Não cria estribos circulares/genéricos novos, ganchos paramétricos de barras livres, múltiplas faixas independentes ou formas inteligentes proprietárias. Também não dimensiona armaduras nem verifica automaticamente normas, ancoragem, cobrimento ou critérios de fabricação. Valores como bitola e mandril são dados explícitos do projetista/gerador.

A [documentação TQS sobre SmartRebar](https://docs.tqs.com.br/Docs/Details?id=1474000011&language=pt-BR) foi consultada como referência de fluxo e separação de definição/representação. Suas regras históricas e unidades mistas não foram copiadas como norma vigente. Não há dependência nem integração de execução com o SDK TQS.

A verificação funcional é em Node e Chromium no modo web. A compilação de instaladores Linux/Windows continua na CI; não equivale a teste de execução nativa. Objetos físicos inválidos não são confirmados; não há uma área pública de objetos incompletos nem um histórico interno separado do aplicativo.
